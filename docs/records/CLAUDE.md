# docs/records

Frozen stories behind how something got the way it is — kept because git history can't
tell them. If code looks strange, a record may be why; comments near such code may point
here.

**The admission test — a record must carry a lesson:**

- a hard-won fix — an incident or messy bug whose journey and reasoning need following;
- a solution we shipped but have to justify, so the next reader doesn't "fix" it;
- good research that found no answer, so it isn't re-run;
- a gap that was found, the posture taken on it, and why.

Plain history with no lesson is deleted, not recorded — git reconstructs what happened.

- **Frozen once written.** A record is a point in time: dated, annotated when needed (a
  clearly marked addendum or header note), never rewritten.
- **Nothing living hides in a record.** A standing practice or open item found in one is
  folded out into the living doc that owns it, leaving a pointer behind.
